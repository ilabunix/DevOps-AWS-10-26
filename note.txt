We have completed multiple Outlook tests of the custom Grafana email notification template.

Final decision:
KEEP the custom subject.
KEEP a custom email body.
STOP trying to use HTML, safeHtml, Markdown bold, or Markdown links.

Our actual Grafana -> email -> Outlook rendering path has shown that:
- Markdown **bold** appears literally
- Markdown [label](url) links do not render cleanly
- safeHtml <strong> tags appear literally
- safeHtml <a href> tags appear literally
- Grafana still uses its native outer email shell

Therefore the custom body should now be intentionally plain-text and optimized for readability using:
- icons
- uppercase section headings
- whitespace
- separators
- conditional fields

Do NOT attempt any more HTML/CSS or Markdown formatting.

==================================================
TEMPLATE REQUIREMENTS
==================================================

Use Grafana Go templating only.

No:
- safeHtml
- <strong>
- <b>
- <a href>
- Markdown **
- Markdown [label](url)
- HTML/CSS
- tables
- custom button attempts

The body must be pure text.

Use conditional rendering for optional values.

Do not display empty sections.


==================================================
ALERT TYPE LOGIC
==================================================

Use:

alert_type = "application"

or:

alert_type = "infrastructure"

to render:

APPLICATION ALERT

or:

INFRASTRUCTURE ALERT

Do not hardcode Compass.

The application name must come from labels dynamically.

GRAFANA OUTER SHELL
==================================================

Do not attempt to remove Grafana's native email shell by changing notification grouping or routing.

We accept that the Grafana shell may remain.

Do not modify:
- group_by
- notification policies
- routing
- receiver behavior

just to change the visual shell.

==================================================
TERRAFORM SCOPE
==================================================

Expected files changed:

- possibly the existing contact point if necessary

Do NOT change:
- grafana_notification_policy
- folders
- dashboards
- data sources
- unrelated alert rules
- routing


==================================================
VALIDATION
==================================================

Run:

terraform fmt
terraform validate
terraform plan

Plan should not show unrelated changes.

STOP if there are unexpected:
- notification policy changes
- alert deletions
- dashboard changes
- folder changes
- contact point replacements


==================================================
TESTING
==================================================

Test in DEV/TEST only first.

Verify:

1. FIRING application alert
2. RESOLVED application alert
3. FIRING infrastructure alert if available
4. RESOLVED infrastructure alert if available

Check Outlook for:

- no literal HTML
- no literal Markdown
- no ** characters
- no <strong>
- no <a href>
- clean line spacing
- icons display correctly
- separator displays correctly
- optional sections disappear correctly
- URLs are clickable
- Silence appears only while firing
- custom subject remains unchanged
- no alert-routing changes


==================================================
FINAL GOAL
==================================================

We are intentionally choosing:

CUSTOM SUBJECT
+
CLEAN PLAIN-TEXT CUSTOM BODY

instead of:
- default Grafana body
- HTML body
- Markdown body

The goal is reliability and readability in Outlook while staying fully inside Grafana/Terraform.
