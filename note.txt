Grafana monitoring is primarily CloudWatch metrics-based rather than log-based. We’re monitoring the EC2/ALB/RDS infrastructure metrics and target-group health, including unhealthy host count for the TaskTop and Keycloak backend health checks.

For CloudWatch Logs, we currently have:

* /tasktop-prod, which contains the EC2 user-data and ssm-data streams — mainly instance startup/bootstrap, TaskTop service startup, firewalld configuration, etc.
* the RDS PostgreSQL log group
* SSM Session Manager shell/session logs

We’re not currently ingesting the detailed TaskTop application/operational logs into CloudWatch for Grafana alerting. ADTs had previously indicated that those application-level logs were not something TechOps needed to alert on, since they are more related to TaskTop operations/activity.

So the actionable TaskTop alerting today is mainly infrastructure metrics and backend health rather than application log-pattern alerts.
