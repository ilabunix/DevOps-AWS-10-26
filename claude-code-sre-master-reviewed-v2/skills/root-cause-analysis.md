# Skill: Root Cause Analysis

Use after or during a significant incident when a defensible RCA is needed.

Workflow:
1. Recover incident/project context.
2. Build an absolute-time timeline.
3. Separate:
   - symptom
   - trigger
   - root cause
   - contributing factors
   - detection gap
   - recovery action
4. Use incident-investigator as the primary specialist.
5. Bring in observability/network/database/software/security specialists only when evidence requires them.
6. Compare evidence for and against each hypothesis.
7. Do not declare root cause until evidence supports causation.
8. Capture corrective and preventive actions with owners/status when known.
9. Checkpoint project-historian.

RCA output:
- Executive summary
- Customer/business impact
- Timeline
- Trigger
- Root cause
- Contributing factors
- Detection and alerting
- Mitigation/recovery
- What went well
- What did not go well
- Corrective/preventive actions
- Evidence/references
